# Protocol v8

The source of truth is `crates/jam-core/src/protocol.rs`. This is an internal, pinned-build protocol, not yet a stable public API.

A connection starts with `Hello(VERSION)`. Every message is a four-byte unsigned big-endian length followed by named-field MessagePack. Frames over 64 MiB and malformed/truncated frames are rejected. Both peers must agree on the exact terminal engine/protocol tag.

Ordinary connections carry one request and one response. State mutations return updated state; pane operations return Ok or Error; capture returns plain terminal text. The CLI's `--json` wraps these responses in JSON for agents. Sending literal bytes is distinct from sending an encoded key or bracketed paste. Modifier bits follow the pinned engine ABI: Shift=1, Control=2, Alt=4, Super=8.

`Attach(pane)` switches to streaming. The pane actor captures a binary terminal snapshot at sequence N, queues it, and registers the subscriber without allowing output to interleave with that operation. Every following Output or Geometry event increments N by one. Mirrors apply exactly this order and resynchronize on gaps. Exited signals process termination. An attach to a saved stopped pane fails until Restart starts its shell.

Each subscriber has a bounded 128-message queue and a thirty-second socket write timeout. An overflowing subscriber is dropped; terminal output continues through the authoritative parser. The client reconnects and receives a fresh snapshot. PTY reader and input queues are bounded separately. An input request is accepted once queued; this is not an acknowledgement that a shell command completed. Input packets are limited to 1 MiB; queue saturation returns an explicit error.

`Client { client, request }` identifies each GUI process. `FocusPane` transfers per-pane size ownership; resize requests from other clients do not change the PTY. `AcquireGui` remains an acknowledged legacy operation but no longer excludes other clients. Object IDs are UUIDs on the server; remote clients qualify references with the saved endpoint ID at their boundary. `HostInfo` and `Directory` expose server-side paths.

`PrepareUpgrade` succeeds only when all panes are stopped and no Git operation is pending. It closes admission for mutations before the installer stops the daemon, preventing a concurrent client from starting a new shell during an idle upgrade.

Confirmed interruptions use `PrepareUpgradeApproved` with the daemon incarnation, build, captured pane IDs, and a `sessions` map from each pane ID to its live `session_generation`. Every PTY launch receives a new generation even when Restart preserves its pane ID. Admission validates the generations and pending operations under the same lock that enters draining; a replacement shell requires new confirmation. An owned lease expires after 120 seconds. `StopUpgrade` validates the token atomically before shutdown; it also accepts an exact owned boot-hold token while startup remains closed. Only the matching owner can abort a lease or commit a boot hold. Saved stopped panes have no live generation after daemon restart.

Version bumps are required when changing wire meanings, snapshot compatibility, default terminal behavior, or advertised terminal capabilities. Never send image state until both snapshot and rendering support it. Remote support must preserve the framing/ordering rules and use an authenticated transport; no TCP listener exists today.

Git checkout operations return a pollable `Operation` ID immediately; `Operation { id }` returns its completion, workspace ID or error. `Worktrees` discovers registered checkouts. Workspaces carry optional Git common-directory, main-checkout and branch metadata. Legacy v1 connections are rejected except through the explicit `jam daemon stop` compatibility path.

Additive capabilities gate newer operations: `move_tab`, `move_pane`, `workspace_names`, `workspace_order`, and `git_summary`. `MovePane` accepts another pane plus Left/Right/Above/Below/Swap, a tab, or a workspace (new tab). It validates the complete proposed layout before replacing state, preserves processes, and removes an emptied source tab. `GitSummary` inspects one checkout outside the server-state lock. `Worktrees` includes a creation-disabled reason for unborn repositories.

`GitSummary` may include an optional `review` object containing `provider` (`github` or `gitlab`), `number`, `url`, `title`, and `draft`. It is absent for older servers, pending/unavailable lookups, or branches without an open request. Hosting API calls use a bounded background cache; they never run while the server state lock is held.

The `agent_usage` capability enables `AgentUsage`, returning cached reports for configured Claude and Codex logins plus profiles discovered in active Jam panes. Reports contain provider, opaque profile/account keys, optional account label, active session count, dynamic quota windows, optional extra usage, checking state, timestamps and sanitized errors. Window percentages/reset times are nullable; failures retain last-success values. Credentials and raw provider responses never cross the protocol. Discovery runs outside the state lock every three seconds while subscribed clients poll; bounded background workers fetch at most once per minute per profile. Removing the last reference to a profile cancels its queued results. Configured logins can report zero active sessions. Monitoring pauses after fifteen seconds without a usage request.

`AuthorizeUsage { profile }`, also gated by `agent_usage`, explicitly queues a Claude credential read which may request local macOS Keychain access. Ordinary polling suppresses all Keychain UI. Authorization accepts only a currently tracked profile and does not change credentials or submit inference requests; the app exposes it only for local Keychain errors. The response acknowledges queuing, with results available through `AgentUsage`.

Find is client-local. The mirror queues a snapshot at a known sequence; a separate worker decodes and scans it. Each query replaces the preceding generation, which is checked throughout scanning. Only counts cross into the UI while matching ranges remain in native memory. A tracked origin accounts for scrolling; changed geometry, discarded history, or replaced text triggers a new search instead of jumping to stale coordinates. No find operation writes input to the PTY.

`InputStream` opens a persistent input-only channel. Clients pipeline ordered `Client` envelopes and drain acknowledgements independently, so typing does not wait for one round trip per key. A failed connection drops pending delivery; no input is automatically replayed.

Workspace model 1 adds persistent `parent` IDs to opened checkout sessions and a live `context` (directory, readiness, repository, checkout path, branch, and creation-disabled reason). `WorktreeOpen` accepts an optional owning `workspace`; `WorktreeCreate` uses the source workspace’s focused directory and adds the result to its top-level owner. The `workspace_containers` capability gates these semantics. Closing with `group=true` follows ownership, not shared repository identity. The original checkout Git metadata remains pinned for grouping.

`coordination_v1` gates `Coordination` requests and responses. The request contains an action and named arguments; `jam coordinate --help` exposes start, list, task, assign, result, complete, cancel, send, inbox, ack, instructions, pause, and resume. Start returns an agent record plus updated `State`; other actions return their record or snapshot. Agent IDs, task IDs, and message IDs are distinct UUIDs. GUI remote responses qualify those IDs as they do pane IDs. Records live in `coordination.sqlite` with WAL transactions; provider socket addresses and tokens are never persisted or returned in snapshots. Provider hooks register session identity and readiness. Accepted transport and acknowledged delivery are distinct states.

`app_settings_v1` adds `Configure { settings }`, which applies the app's enabled providers, worker limit, empty-tab/workspace behavior and checkout-deletion permission to the host. `Settings` returns detected provider executables. The host persists the last applied policy separately from the user's config file so reconnects/restarts retain it. With multiple GUI clients, the last applied settings win. No credentials or local paths are sent. `Node::Empty` represents a retained empty tab; `NewPane { tab }` starts its shell, and `CloseTab { tab }` explicitly closes it regardless of automatic-close preferences. Empty parent workspaces with open worktrees are retained.

`worktree_templates` adds `worktrees_directory` to the host settings policy. Its optional field defaults to `~/wt/{{repo}}/{{worktree}}` when reading older saved policies. Clients omit it when talking to hosts without this capability. WorktreeCreate resolves `{{repo}}`, `{{worktree}}`/`{{wt}}`, and the host's home directory without shell evaluation; explicit paths take precedence. Unknown or incomplete placeholders are rejected before creating directories or branches.

## Pane agent identity

`agent_provider` is the canonical provider for a pane, resolved by the daemon from a registered agent or the current program's explicit OSC 7501 app identifier. `agent_source` is `registered` or `reported`. Only registered agents receive `agent_role` and coordination/recovery controls. Provider names and known aliases normalize centrally. A title or an activity state never identifies an agent.

Reported identity belongs to the current PTY and foreground program. Acknowledging or clearing activity does not end that identity. Returning to the shell, closing the process, or restarting the PTY does. Reported identity is discarded when saved layouts load. Clients use these fields for provider icons and pane, tab, and workspace activity, rather than interpreting reports themselves.

The `workspace_creation_v1` capability supports `WorkspaceCreation { id, incarnation, request }` for new and opened workspaces and worktrees. The server returns an `Operation` receipt. Retrying the same ID on the same daemon resumes that operation. A new workspace uses the proposed ID. Opening an existing workspace returns its existing ID.
